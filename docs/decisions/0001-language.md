# 開発言語の選定

## 要件

Orca のプラグインとして、エージェント間の依頼をパネルに表示する。
Orca 本体と通信するプラグイン側の処理と、ブラウザー上のパネル UI を同じ言語で書く。
両者がやり取りするメッセージの形を１か所で定義し、形の食い違いを実行前に見つけたい。

## 候補

TypeScript と JavaScript を比較する。

- TypeScript: Orca が配布するプラグイン API の型定義をそのまま使える。
  メッセージの型を共有でき、形の食い違いを `tsc` の型検査で実行前に検出できる。
  型検査とビルドの手順が増える。
- JavaScript: ビルドなしで実行できる。
  API とメッセージの形の誤りは実行するまで分からず、テストで補う範囲が広がる。
  JSDoc で型を書く方法もあるが、型定義の共有と検査の厳密さは TypeScript に劣る。

## 選定理由

TypeScript を採用する。
プラグイン側とパネル UI でメッセージの型を共有し、
Orca の API との食い違いを実行前の型検査で検出できるため。
型検査とビルドの手順が増えるが、規模が小さいため負担は小さい。

開発の設定は次のとおりとする。

- パッケージ管理は pnpm を使う。dev-standards の node-npm は npm を前提にするため、mise-project を使う。
- 各タスクから package.json の scripts を呼ぶ。lint と整形には Biome、テストには Node.js のテストランナーを使う。
- 検証の範囲はリポジトリ全体とし、OS 固有の検査はない。
